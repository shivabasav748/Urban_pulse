# 🚖 Urban Pulse — Hack Valley PS 02

> **A ride-hailing prototype with 5 advanced features: demand forecasting, zone-based surge pricing, ride pooling, fair driver allocation, and intelligent reassignment.**

---

## 📌 Problem Statement

**Hack Valley PS 02** — Build a full ride-hailing lifecycle (rider → dispatch → driver → completion) with demonstrable advanced features, using clearly-labelled simulated data.

---

## 🏗️ Architecture

```
flowchart LR
  Browser[React + Vite SPA]
    --> Rider / Driver / Admin / Demo Simulator
  Browser -- supabase-js: Auth · rpc() · select --> PG[(Postgres + PostGIS · RLS + SECURITY DEFINER RPCs)]
  PG -- Realtime postgres_changes --> Browser
  ML[ml/train.py · sklearn] -- seed SQL: observations + forecasts --> PG
```

**Key architectural decision:** GitHub Pages is static-only, so there is **no Node/Express API**. React talks directly to Supabase; every integrity-critical operation is a `SECURITY DEFINER` Postgres function called via `supabase.rpc()`. This eliminates a service to build, host, and maintain during judging. See [`docs/IMPLEMENTATION_PLAN.md`](docs/IMPLEMENTATION_PLAN.md).

## 🎯 5 Advanced Features

| # | Feature | Implementation |
|---|---------|----------------|
| A | **Demand Forecasting** | `ml/train.py` — HistGradientBoosting on 8 zones × 42 days synthetic history; MAE vs naive baseline shown in UI |
| B | **Zone Surge Pricing** | Gap-based surge: `clamp(1 + 0.15 × max(0, forecast/supply − 1), 1, 2.0)`; heatmap + repositioning arrows |
| C | **Ride Pooling** | Greedy 2-rider matching (pickup ≤ 1.5 km, drop ≤ 2.5 km, detour ≤ 40%), stop-order comparison, 30% fare split |
| D | **Fair Allocation** | 4-component scoring: ETA (0.45) + workload (0.25) + reliability (0.20) + idle time (0.10); score bars in Admin UI |
| E | **Reassignment** | On reject / timeout / delay → exclude driver, re-dispatch, increment attempt counter; cap 5 attempts |

## 🚀 Local Setup

### Prerequisites
- Node ≥ 22, pnpm ≥ 10
- Python 3.x, pip
- Docker Desktop (for local Supabase)
- Supabase CLI via `pnpm dlx supabase`

### 1. Clone & install
```bash
git clone https://github.com/shivabasav748/Urban_pulse.git
cd Urban_pulse
pnpm install
```

### 2. Configure environment
```bash
cp .env.example .env.local
# Fill in VITE_SUPABASE_URL and VITE_SUPABASE_ANON_KEY
```

### 3. Start local Supabase (Docker required)
```bash
pnpm dlx supabase start
pnpm dlx supabase db reset   # applies migrations + seed
```

### 4. Train the forecast model
```bash
cd ml
pip install -r requirements.txt
python train.py
# Writes supabase/seed_forecast.sql and ml/metrics.json
cd ..
pnpm dlx supabase db reset   # re-apply with forecast data
```

### 5. Start dev server
```bash
pnpm dev
```

## 📊 Data Model (key tables)

| Table | Purpose |
|-------|---------|
| `profiles` | id → auth.users, role (rider\|driver\|admin), name |
| `drivers` | location geography, online, idle_since, rides_today, offer stats |
| `rides` | full lifecycle, fare_breakdown jsonb, surge, pool_group_id |
| `ride_offers` | per-attempt offer with score_components jsonb |
| `ride_events` | append-only audit log |
| `zones` | 8 Bengaluru zones with PostGIS polygons |
| `demand_observations` | historical demand, rain, incident flags |
| `demand_forecasts` | predicted vs actual per zone per 30-min bucket |
| `settings` | global weights, timeouts, surge cap, sim_clock |

See [`docs/DATA_MODEL.md`](docs/DATA_MODEL.md) for full DDL and indexes.

## 🗺️ Supabase RPC Contract (replaces REST)

| RPC | Caller | Action |
|-----|--------|--------|
| `estimate_ride` | rider | Distance, ETA, fare breakdown, nearby drivers |
| `request_ride` | rider | Insert ride → dispatch() |
| `dispatch` (internal) | — | Score candidates, create pending offer |
| `respond_offer` | driver | Accept/reject → re-dispatch on reject |
| `advance_ride` | driver | Validated state transition + timestamps |
| `cancel_ride` | rider/driver | Cancel; driver cancel → re-dispatch |
| `sweep_exceptions` | any authed | Expire timed-out offers, flag delayed arrivals |
| `zone_intelligence` | all | Forecast, supply, gap, surge, repositioning |
| `create_pool` | rider/admin | Validate + persist pool group |
| `admin_metrics` | admin | Waiting time, ETA error, utilisation, completion |

Full contract in [`docs/API_CONTRACT.md`](docs/API_CONTRACT.md).
